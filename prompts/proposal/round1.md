这是第一轮。请按自己的席位研究视角独立检索、思考，并提出一个主方案。不要读取或等待其他席位的意见。

中文正文建议约 800–1500 字，重点写：
1. 一句话主张与明确研究问题；为什么值得解决。
2. 核心机制、必要公式与假设；真实省掉/复用的计算及新增开销。
3. 至少三份核查过的一手资料，以及最相近方案与你方案的实质差异。
4. 自己认为最可能推翻方案的一个反例或技术障碍。
5. 按 research_brief.md 写明的硬件条件可运行的最小判别实验：变量、必要对照、指标、观察到什么就停止。背景没给硬件就写清需要什么，不要假设自己有。
6. 检索词、检索范围与尚未核查的部分。

正文末尾附一个合法 JSON 代码块，按真实情况填写。agent_id 必须是你自己的席位 ID（见系统提示），proposal_id 为 P- 加自己的 ID：

```json
{
  "agent_id": "你的席位ID",
  "round": 1,
  "proposal_id": "P-你的席位ID",
  "title": "主方案名称",
  "closest_work_urls": ["实际核查过的URL一", "实际核查过的URL二", "实际核查过的URL三"],
  "retrieval_status": "completed 或 partial"
}
```

`retrieval_status` 必须如实填写，三选一：

- `completed`：你确实读到了至少三份一手资料的机制段/方法段，且做过一轮针对最相近工作的定向查重，能说出检索词与范围。
- `partial`：检索做了，但明确知道还有未覆盖的近邻（例如没查某个方向的实现、只读到摘要、时间不够）。选它不扣分，`audit` 会把你列进 `retrieval_partial_seats`，终稿会照实写。
- `blocked`：检索根本没做成。此时主持会把该席位记为未完成，不把它当成已有文献支持的方案。

**不要为了好看写 `completed`。** 上一场有三个席位自述查重没做完却写了 `completed`，结果缺口是在 audit 之后才被翻出来的，等于把问题推给了报告。现在选 `partial` 是安全的，它只是要求你在正文里说清缺什么。
