这是第一轮。请按自己的席位研究视角独立检索、思考，对 research_brief.md 提出的问题给出你自己的立场。不要读取或等待其他席位的意见。

先判断这个问题问的到底是什么：它可能是"某个做法是否成立"、"某个说法有没有证据"、"两种方案哪种更好"。如果题目本身有歧义，先写清你按哪种理解作答，以及另一种理解下答案是否会不同。

中文正文建议约 800–1500 字，重点写：

1. 一句话立场，以及它到底断定了什么范围（在什么对象、什么数据、什么条件下成立）。
2. 支撑这个立场的机制论证：为什么会这样，而不是别的样子。有式子就先定义符号和假设。
3. 至少三份核查过的一手资料：每份写清它测了什么、结论是什么、读到的层级，以及它支持你还是反驳你。
4. 反方最强证据：你能找到的最有力的相反结果或相反论证。不要写一个稻草人。
5. 什么观测会让你改变立场：具体的量、具体的方向。
6. 检索词、检索范围与尚未核查的部分。

正文末尾附一个合法 JSON 代码块，按真实情况填写。agent_id 必须是你自己的席位 ID（见系统提示），position_id 为 S- 加自己的 ID：

```json
{
  "agent_id": "你的席位ID",
  "round": 1,
  "position_id": "S-你的席位ID",
  "stance": "支持 / 反对 / 有条件成立 / 证据不足",
  "evidence_urls": ["实际核查过的URL一", "实际核查过的URL二", "实际核查过的URL三"],
  "retrieval_status": "completed 或 partial"
}
```

`stance` 只能取上面四个值之一：`支持`、`反对`、`有条件成立`（正文里必须写清条件）、`证据不足`（你查过但没有足够材料判断）。选 `证据不足` 不是弃权，它在投票轮也会作为一条独立结论参与表决。

`retrieval_status` 必须如实填写，三选一：

- `completed`：你确实读到了至少三份一手资料的方法段/结果段，并且查过至少一个可能反驳你的方向，能说出检索词与范围。
- `partial`：检索做了，但明确知道还有未覆盖的部分（例如某个反对方向的文献没找到、只读到摘要、时间不够）。选它不扣分，`audit` 会把你列进 `retrieval_partial_seats`，终稿会照实写。
- `blocked`：检索根本没做成。此时该席位会被记为未完成，不把它当成有证据支撑的立场。

**不要为了好看写 `completed`。** 选 `partial` 是安全的，它只是要求你在正文里说清缺什么。
