这是中间轮（不是最后一轮，也不是投票轮）。你已能看到其他席位此前各轮的原文。请做三件事。

## 一、检索（不能省）

本轮必须重新检索，不允许只凭已有印象评审。至少做两轮不同角度的查询，并在正文里列出你实际用过的查询词、查到的范围、以及读到了哪一层（完整方法段/部分正文/仅摘要）。重点查的是：

- 你打算反对的那条立场，有没有反例已经被人做过实验；
- 你打算支持的那条立场，最强反证是什么，你有没有认真找过；
- 你此前没有覆盖的方向（同期工作、非 arXiv 的会议论文、工业界技术报告）。

自己此前的判断可以被推翻，但不能因为别人这么说就接受——关键论文自己打开结果段核对。

## 二、互评

至少实质回应两个其他席位。写清你针对的是哪条具体主张、你的立场（支持/反对/建议修改）、论据，以及什么证据能推翻你现在的判断。不要为了辩论强行反对，也不要为了和气强行支持。

特别要指出**分歧的根源**：如果两个席位结论不同，是因为读了不同文献、还是对同一结果的外推程度不同、还是对问题本身理解不同？把这一点写清楚，比多写一段论证更有用。

## 三、收敛：澄清、收窄或放弃

本轮允许你修改自己的立场，条件是给出改变的理由。也允许你把自己的立场收窄成更精确的条件式（例如从"成立"改为"在 7B 以上模型、长上下文设置下成立"）——但要说明收窄后的版本是否还能回答 research_brief.md 的原始问题。

如果你认为自己的原立场站不住，直接说出来，并说明证据。允许本轮结束时你放弃原有立场——这是有效结果，不是失败。

## 输出

中文正文，建议 900–1600 字。正文末尾附一个合法 JSON 代码块，按真实情况填写：

```json
{
  "agent_id": "你的席位ID",
  "round": 本轮轮次,
  "searched_queries": ["实际用过的查询一", "实际用过的查询二"],
  "evidence_urls": ["本轮实际读到的最相关证据URL"],
  "responses": [
    {"to_agent": "其他席位一", "stance": "support", "claim": "针对哪条主张、为什么，附正文证据"},
    {"to_agent": "其他席位二", "stance": "modify", "claim": "针对哪条主张、建议怎么改，附正文证据"}
  ],
  "position_change": {
    "changed": false,
    "from": "如果你改了口径，原来的一句话立场",
    "to": "收窄或改动后的一句话立场",
    "why": "哪条证据或哪个席位让你改的"
  }
}
```

`searched_queries` 至少两条，且必须是你本轮真的敲进检索工具的查询——`audit` 会检查条数，终稿会照实引用。`responses` 里对自己的条目算自我修订，不计入回应他人的数量。立场没变时 `position_change.changed` 写 false，`from` 和 `to` 留空字符串。本轮不投票，不要输出 votes。
